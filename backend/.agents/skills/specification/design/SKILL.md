# Design Skill

Start from approved Business Requirements, Software Requirements, and Technology Architecture.

1. Locate the change in the existing architecture when repository evidence exists.
2. Define the modules/components involved and their responsibilities.
3. Ensure the design satisfies the functional and non-functional requirements that materially affect the solution.
4. Describe only the interactions and data/control flows that matter to the increment.
5. Identify important interfaces and design decisions.
6. Add a simple architecture diagram when it clarifies the design.
7. Keep the design implementable without becoming an exhaustive HLD/LLD document.
