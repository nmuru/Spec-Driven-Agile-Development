# Software Requirements Skill

Start from approved Scope and Business Requirements, then use project.md and repository evidence when available.

1. Convert user-visible behavior into precise software behavior and system responses.
2. Capture relevant functional and non-functional requirements.
3. Check performance, security, privacy, reliability, accessibility, data, interfaces, integrations, and operational constraints where they materially apply.
4. Preserve explicit acceptance conditions and business rules.
5. Do not invent targets or implementation choices when the evidence does not establish them.
6. Keep the result prompt-oriented and concise while retaining the important substance normally expected from an SRS.
